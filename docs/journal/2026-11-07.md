## TASK-204: CoreGS 2.0 never compiles a pipeline during play (branch `task/204-no-ingame-compile`)

Owner brief from a player crash on rc15: RX 6750 XT, AMD driver 25.10.30.02, CoreGS 2.0 at 4x, `0xC0000005` inside a
pipeline compile on the `spec_worker` thread. The private logs (`crash-log-1532`) were read for the diagnosis and never
copied into the repository.

**Read from the player's `game.log`:** 301 variants recreated at start in 227.7 ms (0.75 ms each: disk-cache hits); then
44 new keys requested during play, `compile_ms` 227.7 -> 26,517.1 ms with `compile_max_ms` 1,047.9 ms; `compiling.bin`
held the key in flight when the process died; `quarantine.bin` had 6 keys from earlier prepares (the launcher had run 14
attempts in an earlier session). So the TASK-170 guard and the TASK-170b retry loop covered the prepare only, and
`PreparedStamp` did not hash `variants.bin`, so a session that recorded new keys left the prepare reporting "ready".

**What changed (native).** `native/hw_gs/core2/core2_gpu.cpp`:
- `specialised_pipeline` no longer compiles an unknown key: it records it in `variants.bin` (through `specKnown`), counts
  it in `statDeferred`/`specDeferredBatches`, and returns null so the batch keeps the uber pipeline. A repeat of a
  deferred key is counted too. The switch `GT4_CORE2_INGAME_COMPILE=1` restores the old path; without
  `GT4_HW_SHADER_CACHE` there is no list to defer to.
- `queue_known_variants` recreates the recorded variants only when `prepared_for(prepared_stamp())` is true, so a play
  session only asks the driver for what the prepare compiled (a disk-cache hit); otherwise it logs the missing prepare
  and keeps uber.
- `PreparedStamp` gained `variants` (FNV-1a of the keys) and `variantCount`; the prepare writes the stamp of the list it
  compiled, so a recorded key makes the next Play prepare again. `variants_to_prepare` reports how many keys came from the
  sessions' list.
- `open_compile_guard`: a key left in `compiling.bin` is quarantined at once when the game starts (a play strike); the
  prepare keeps TASK-170c's two strikes.
- `[core2] specialised pipelines=` gained `deferred=N deferred_uber_batches=M`; the prepare line names the recorded keys.
- `Core2Counters` gained `specPipelines`, `specDeferred`, `specDeferredBatches`, `uberBatches` for the fixtures.

**What changed (launcher).** `gt4l-core/src/launch.rs` parses `shaders recorded R`;
`gt4l-platform/src/game.rs` carries the count out of every attempt; `gt4l-tauri/src/commands.rs` logs
`shaders: R recorded keys compiled`. The Play flow already runs the prepare every time and opens the progress window on
the first `shaders progress 0 T`, which the stamp change now makes happen when `variants.bin` grew.
