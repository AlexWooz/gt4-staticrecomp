## The dither option: the CT16 pin, the switch and the A/B (TASK-090, branch `task/090-dither`)

One branch from `task/090-coregs3` at `a59ce9c9` (worktree `O:/Antigavity/gt4-wt-090-dither`). The owner's decision of
02:31 is implemented: the CT16 dither is removable in the modern path and the faithful modes keep it.

- **Where the dither is (C).** Three writers, two dither. The offline CT16 present model (`apply_present_ct16`) applies
  the captured **DTHE 1 / DIMX `0x0001044501100554`** entry per 4x4 cell (six negative and ten non-negative entries,
  mean -1.125), COLCLAMP, the five-bit truncation and `<< 3`; the decoded matrix is `[-4 -3 -3 0] / [0 +1 +1 0] / [-3 -4
  -4 0] / [+1 0 0 0]`, and at 3x a cell is 12x12 output pixels. The CoreGS 3.0 live fragment stages
  (`coregs3_present.frag`, `coregs3_world.frag`) write 8-bit RGBA8 words and never dither. The CoreGS 2.0 composed base
  dithers through `hw_process_pixel` at native 4x4 cells; it is faithful output and is not changed.
- **The switch (C).** `GT4_COREGS3_DITHER=0|1` (`native/coregs3/coregs3_dither.hpp`; absent/empty = 0; only `0`/`1`,
  anything else refused with the value named), read by the offline tool (which also takes `--dither 0|1` as an override)
  and by the live present (parsed and reported; its pixels do not change). `1` is the captured conversion; `0` is the
  modulated 8-bit colour with COLCLAMP only, skipping the dither **and** the five-bit truncation because they are one
  scanout model (the truncation alone would leave 32-level banding against 129 levels).
- **Offline A/B (C).** A-Spec capture, scene frame 0 (VBlank 7600), world + the whole post chain, 1920x1344, same
  command with `GT4_COREGS3_DITHER=1` and `=0`: PSNR **33.46 dB**, mean |diff| **4.51**, max **11**, **2,473,548
  pixels (95.9%)** differ, mean signed **-4.43**; faithful is 100% divisible by 8 with 32 levels, off 5.4% with 129.
  On a flat road crop (1824,1152,48,48) the off image is a constant 63/53/41, the faithful one the 12x12-cell pattern of
  56/64, and against the reference the faithful model is PSNR **20.67 / mean 21.48** versus **19.22 / 26.22**; within-cell
  deviation reference **4.11**, faithful **2.94**, off **1.04**. Crops and the amplified difference are in
  `build/evidence-dither/`.
- **Live A/B (C).** Night race, 3x, six dumped frames 6600-7600: present1 vs present0 differs on 0.27-2.40% of the
  pixels and the same-config control present0 vs present0b on 0.25-2.30% (the known cross-run overlay noise), and a sky
  block the live world draws is identical across present0, present1 and present0b (mean 23.197/21.671/15.781, 15.9%
  divisible by 8, 28 levels) against the base's 100% divisible CT16. So the switch changes nothing in the CoreGS 3.0
  pixels, and the base dither remains until phase 4. `GT4_HW_DITHER=off` does not remove it: the option is parsed in
  `hw_gs_options.cpp` but never assigned to `decide::Options::dither_enabled`, and the measured `off` against
  `off + GT4_HW_DITHER=off` difference is **0 pixels** (a pre-existing CoreGS 2.0 gap, recorded).

## Live world picture round: the emitted fog, the GS bilinear and the tap state (TASK-090, branch `task/090-live-world`)

- **The live in-memory tap (C).** The GS worker already buffers every VU1 job's PATH1 GIF records to snapshot its texture
  windows; `coregs3_live_world` now keeps those records too (`note_job_stream`, with a global emission sequence and the
  job id) and `build_tap_snapshot(frame.vblank, addresses, ...)` synthesizes the `.gt4tap` record view for exactly the
  packet addresses the frame's world items name. The visibility of the state-only records was the first bug: the VU1
  emits the TEX0/TEX1/CLAMP writes in vertex-less records that can belong to another job, so the snapshot keeps **every**
  stored record in emission order (the offline tap file's walk) while the source records stay filtered to the requested
  addresses. The world build calls `build_frame_texture_table` with `use_tap = true` on that snapshot, so the offline
  pairing attaches the emitted per-item state, the emitted UVs and the per-vertex fog; the pixels still come from the

## The native HUD anchored per display aspect (TASK-090/TASK-214, branch `task/090-hud-aspect`)

## CoreGS 3.0 car pass study: the live present binds only the pre-texture base path (TASK-090, branch `task/090-car-study`)

Read-only study in `O:/Antigavity/gt4-wt-090-car-study` (branch from `task/090-coregs3` at `e7e67e2d`). No native source
changed; tools and evidence under `build/` (gitignored). Document: [COREGS3-CAR-PASS-STUDY](docs/COREGS3-CAR-PASS-STUDY.md).

- **Question.** Why does the live `present` car read as a neutral grey/dark silhouette while the offline textured render
  (and the round-20 reflection) draws the red Mégane with paint, lamps and reflection?
- **Method.** Built the branch tools (`GT4_HW_GS=ON`, offline tool without the EE library), filtered the v6 ALL_DRAWS
  capture `night-mip.gt4scene` (VBlanks 7398-7402, 285 draws/frame; 116 car draws) to its car pass with a small helper
  linked against `gt4_coregs3.lib`, rendered frame 0 at 1920x1344 in four variants (`--no-textured`, textured,
  `--no-reflection`, per draw for all 116) with the capture's tap/vram sidecars, and dumped every car item's binding
  and GS state through the same `build_frame_texture_table` the offline renderer uses.
- **Root cause (Confirmed).** `Impl::build_frame` (`native/hw_gs/coregs3/hw_coregs3_present.cpp:1016`) emits only
  position + lit vertex colour per vertex (`PresentVertex`, `:132`); `coregs3_present.frag` stores it opaque with alpha
  255; the car pass never builds a `FrameTextureTable`, never samples a car texture and never binds the per-item

## The B-Spec split black-3D fix (TASK-090 phase 4 follow-up, branch `task/090-2d-split`)

The live-world round found that the 2D split (default) blacked out the **night B-Spec race**: frame luma 2.291 with only
the HUD, against 22.377 with `GT4_COREGS3_2D_OVERLAY=0`; the A-Spec scene rendered 28.02 with the split on.

- **The cause (C).** The B-Spec stream draws, after the present blit and the HUD sprites, a **full-screen unblended
  alpha-only sprite into the display buffer** (PRIM 0x006, untextured, TEST 0, FRAME.FBMSK 0x00FFFFFF, TBP0 0x3C00,

## The car pass textures and reflection, first implementation (TASK-090, branch `task/090-live-world`)

The car-pass study (`docs/COREGS3-CAR-PASS-STUDY.md`, merged at `3d2b5a54`) showed the live car pass was the offline
renderer's pre-texture base path. This round implements its fix list:

- **Store decoupled (C).** `live_world::active()` is the store (on in `present`), `world_enabled()` reads
  `GT4_COREGS3_LIVE_WORLD`; the hooks install the job-source sink in `present` and only the world draw follows the world
  switch, so the car-only A/B keeps its live job records; the backend's VRAM-base copy follows the store.
- **Car table and ranges (C).** `build_car_table` runs on the frame's first tick under `world_mutex`: the car items'
  live job records, `build_tap_snapshot`, `build_frame_texture_table` with `use_tap`/`reflections = true`/
  `world_channels = false`, the shared atlas, and the per-item `TEST/ALPHA/FBMSK/FOGCOL/PRIM` state, blend equation,
  DATE and ZMSK flags. `build_frame_textured` shades the mesh with `shade_mesh_items` and emits one range per item with
  its TEX0/CLAMP/atlas rectangle and UV, or the reflection texgen S,T (a vertex whose coordinate cannot be computed
  skips the item, counted).
- **Fragment (C).** `coregs3_car.vert`/`.frag`: the world sampler, MODULATE/TCC, fog, the alpha test, the destination
  alpha test (DATE/DATM against the display word's alpha MSB), the 8-bit ALPHA blend (read-modify-write, `((A-B)*C)>>7+D`,
  COLCLAMP, alpha = As), FBMSK and the post chain; untextured items keep the offline prefetch write (lit colour, alpha
  255). Two pipelines: depth write and no depth write (ZBUF.ZMSK=1).
- **A/B and counters (C).** `GT4_COREGS3_CAR_TEXTURES=0` keeps the legacy path; the F8 report prints the car table's
  textured/reflection/no_record/refused/atlas counts.
- **Measured (C).** The car changes: 26,877/52,900 px in the player box, mean 9.26 levels. Near-car mask means: live
  legacy 20.5/20.1/19.6, live textured 9.7/8.1/8.3 (red-dominant 11.4%), offline textured 9.5/9.3/8.4 (6.5%). The

pre-existing diagnostic path that was never validated with non-zero samples). The +/-5% fragment gate stays unmeasured
