- Read the current input path (`native/host_io.cpp`, `native/pad_mapping.*`, `native/controls.*`,
  `native/window.cpp`, donor `iop/sio2.cpp`), the wheel work on the 1.3.0-rc15 line (`docs/WHEEL.md`,
  `docs/WHEEL-NATIVE-DFP.md`, `native/usb_dfp.cpp`, `native/wheel.cpp`, TASK-121/123/181/192) and the decomp
  `private/slice151-research/gt4-decomp` at `e0b70c4d6`.
- Findings (details and labels in `docs/H-SHIFTER-CLUTCH-STUDY.md`):
  - GT4's input actions are sequential shift up/down and reverse; no clutch action and no H-gate action in the
    ELF action table. The DFP input report (8 bytes) has steering, 14 buttons, hat, throttle and brake; no
    clutch or gate. The rc15 wheel work says direct gear selection and manual clutch are outside its scope.
  - The HUD does have `setGear`, `setClutch`, `setAutomaticTransmission` and `setShiftTimingLamp` (Confirmed
    symbols). The clutch flag's source and any drivetrain clutch torque are Unknown; the matched decomp has no
    clutch physics symbol.
  - MT/AT: `Automobile__isFullManualTransmission` (0x003481C8) reads `Automobile + 0x546 == 6`; called from
    `RaceBase::initializeDynamicsConductor` (0x00388790, call at 0x00388844) and from `func_0037AD40`
    (call at 0x0037AD70).
  - Gear-selection candidate: `func_0037AD40` / `func_0037ACD0` / `func_0037AD10` / `func_0037BC20` /
    `func_0037BC68`, with a 12-entry table at `0x006211E8` and a gear field at `+0x180`. The code path is
    high confidence; the player-car ownership and the physics gear field are Unknown.
  - Input path: host -> `ps2::set_pad_buttons` -> SIO2 HLE -> game. The `RaceInput` singleton is at
    `0x00622B60`; its pad word is at `0x00622CE8`. A VBlank guest-RAM hook already exists
    (`widescreen_hold_at_guest_vblank` in `vblank_sync`), but a direct gear write is a mod and is not
    recommended.
- Recommendation: implement H-shifter as button emulation first (pad R2/L2 on main, DFP R1/L1 on the rc15 wheel
  branch), with a pure shift sequencer and the game's own rules; add a read-only gear probe only if needed; do
  not implement direct gear writes or a clutch in the first version.
- Numbering note: this study is TASK-215; the 1.3.0 line already uses TASK-104 for the launcher save import.

## TASK-215 deep follow-up: direct gear and clutch mod study

- Read-only on source. Worktree `O:\Antigavity\gt4-wt-215-hshifter-deep`, branch `task/215-hshifter-deep`, based on
  `task/104-hshifter-study` at `5c2373bd`. No game code, build, pin, save or card changed.
- Owner directive: modify the game (not button remapping): improve/add the clutch, add an analog clutch pedal, gears
  apply directly, and reverse is a gate position R, N, 1..6 (downshifting past 1 goes through N then R).
- Method: decoded the reconstructed ELF (Capstone MIPS64 LE plus direct immediate/load-store scans), read the decomp
  at `e0b70c4d6`, resolved vtables through their RTTI typeinfo functions, and cross-checked every field between the
  consumer code and the HUD.
- Findings (details and labels in `docs/H-SHIFTER-CLUTCH-MOD-STUDY.md`):
  - Correction: the first study's `func_0037AD40` group is `CameraSys::CameraOnBoard` (vtable `0x0067A5D8`, RTTI
    name `Q29CameraSys13CameraOnBoard`); the `+0x180` field and the `0x006211E8` table are camera state, not gears.
  - Correction: the HUD gear/clutch setters are called from `RaceDisplay::update` (`0x0039DBB8`), which reads
    `Automobile + 0x624` and `Automobile + 0x626` through the player car chain
    `RaceDisplay + 4 -> organization + 0x60 -> Cars + 8 -> item + 0x18`.
  - Real drivetrain: gear at `Automobile + 0x624`, clutch state `+0x626` (0 open, 1 engaged, 2/3 slipping),
    engagement `+0x618`; all fields of the drivetrain block at `Automobile + 0x104`. Gear numbering is 0 = R,
    1..count forward; there is no neutral gear value, neutral is clutch open.
  - Per-tick: control update `0x00349418` -> DynamicsConductor per-car loop `0x0034DB10` -> drivetrain tick
    `0x003535B0` -> engine force `0x0036D818`; HUD `RaceDisplay::update` later. The selector (`func_0036C8E8`,
    jump table `0x0069F840`, `func_0036C160`) produces the target; `func_00351DC8`/`func_0036BEB8` write the gear.
  - Clutch: GT4 has an automatic clutch state machine (`func_00350FB8`), a type-3 direct mapping
    (`func_00351178`), rpm sync (`func_003519B8`) and a torque gate on `+0x626` (`func_0036D818` at `0x0036D870`).
    The player has no clutch input; the mod can drive the states and cut torque. Continuous slip torque would need
    a force-scale patch.
  - Direct gear: write the gear byte with the clutch open, clear the shift step/delay; a one-instruction patch table
    can inject the host clutch state, target gear and HUD R/N character through the existing `0x7F00` block
    (TASK-080 pattern). Candidate old/new words are in the study; not built or tested.
  - R/N: both use gear 0 with the clutch open/closed; the HUD gear-0 character can be host-selected (`R` or `N`)
    with one instruction patch at `0x003A6F54`. The game's reverse lock (0.2778 m/s) and rpm clamp stay in charge.
  - Replays: the recorder stores the control packet, not the gear/clutch; the mod must be disabled in replay,
    ghost and autodemo. Saves: race state only; never write car data.
  - Boundary: owner decision 0073 (2026-11-11) makes gameplay mods in scope and shipped in the same bundle, opt-in
    and off by default; the base game and the faithful modes keep exact physics, timing, AI, saves and gameplay
    read-backs. The implementation can use a separate derivative ELF/library profile inside that bundle; the
    button-emulation front remains the faithful feature.
- PoC plan: live read-only probe (player index, gearbox type, VBlank ordering, N glyph), then the gate/clutch state
  machine, the patch table and host block, the host G27 input, and the owner test. Estimate 4-6 weeks, medium risk.
- Next: owner decision on the mod scope and the analog-feel expectation; no implementation started.
