## Live world picture round: the emitted fog, the GS bilinear and the tap state (TASK-090, branch `task/090-live-world`)

Continuation in the same worktree (`O:/Antigavity/gt4-wt-090-live-world`, from `64839cdb`). The live world already
selected, textured and shaded the captured course; this round restores the three largest picture gaps the counters
named, without a capture file and without a per-item guess.

- **The live in-memory tap (C).** The GS worker already buffers every VU1 job's PATH1 GIF records to snapshot its texture
  windows; `coregs3_live_world` now keeps those records too (`note_job_stream`, with a global emission sequence and the
  job id) and `build_tap_snapshot(frame.vblank, addresses, ...)` synthesizes the `.gt4tap` record view for exactly the
  packet addresses the frame's world items name. The visibility of the state-only records was the first bug: the VU1
  emits the TEX0/TEX1/CLAMP writes in vertex-less records that can belong to another job, so the snapshot keeps **every**
  stored record in emission order (the offline tap file's walk) while the source records stay filtered to the requested
  addresses. The world build calls `build_frame_texture_table` with `use_tap = true` on that snapshot, so the offline
  pairing attaches the emitted per-item state, the emitted UVs and the per-vertex fog; the pixels still come from the
  live job store. Records are one guest frame old (the same lag as the textures), counted; the snapshot is bounded
  (64 MiB).
- **The live VRAM base (C).** The second bug was the empty base: the emitted state can name a page the item's own job did
  not write (a carried texture), and with no base image the decode refused it (`sidecar does not cover texture block
  12891`). The backend's VBlank flush now copies the GS local memory over the measured world range
  `0x2BC0..0x3FFF` into the store (`note_vram_base`), the same role the `.gt4vram` vblank record plays offline; the job
  records take precedence and the base serves the carried pages. At VBlank 7400 the table bound **1,262 items from the
  emitted state** (offline: 1,268), 41 record fallbacks, **0 decode refusals**, 0 state refusals.
- **Fog (C).** The live world vertex carries the emitted fog byte (a `noperspective` varying: the GS fog lane has no Q
  and is interpolated screen-linearly); the fragment applies the GS integer mix toward FOGCOL
  (`(f*c + (255-f)*fogcol) >> 8`, alpha unchanged) before the alpha test and the FBMSK merge, the arithmetic of
  `coregs3::apply_vertex_fog`. A vertex without an emitted fog value keeps the 255 identity and is counted
  (`fog_missing`); the sky pass stays unfogged. `GT4_COREGS3_WORLD_FOG=0` is the A/B. A formula study on the tap found
  the fog is **linear in the clip-space w per item/draw** (697 of 802 varying items fit within 1 level) but with
  per-item constants not present in the captured packets: a global fit on the captured scene parameters is 10-14 levels
  off, so the tap-free route is the emitted record, not a guessed formula (`--fog-dump` in the offline tool is the
  evidence instrument).
- **GS bilinear (C).** A linear item (TEX1 MMAG = MMIN = linear, the only mixed-free form the binding accepts) samples
  with the GS bilinear: `(u-0.5)` to a floor base, 4-bit weights, the four taps wrapped independently with the four
  CLAMP modes, sum >> 8, then MODULATE — the arithmetic of `coregs3::sample_texture`.
  `GT4_COREGS3_WORLD_FILTER=nearest` is the A/B; `filter_linear` counts the items sampled bilinear (3,769 at VBlanks
  6600-7400).
- **Untextured items (C).** With the emitted state and the base, the record-path refusals bind the pixels the draw
  actually sampled: the pre-round record path left 2,938 of the window's 5,112 world items untextured (2,886 of them
  refused); the same window now has 52 untextured (8 no-record, 44 no-UV) and **0 refusals**. The remaining untextured
