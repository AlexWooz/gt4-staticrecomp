## TASK-213 Phase 2a: host-native page, the gate (branch `task/213-native-settings`)

The owner chose a host-native page with the game's own widgets, reached from Options. The page API is script-event
driven: `page_util.ad`'s `start_page` pushes an `MFunctionEvent`; `_start_page` runs `context.transition.panOutIn`, the
`CursorRoot` cursor, `context.startPage(next_page)` and `flushKeyEvent`; back ends with `context.finish()`.
`MRenderContext.startPage` `0x0022BC20`, `closePage` `0x0022FA08`/`0x0022BD98`, `getCurrentPage` `0x0022BE00`,
`pushEvent` `0x0022B9F0`, `finish` `0x0022BEA0`. The live state: `mRenderContextPS2` at `0x01021FF0`, 26
`mRootWindow` roots (ScreenRoot `0x00F77200`) and the Options root `mScrollWindow` `0x01FDA8A0`; the hidden
`MonitorRoot` tree exists.

**Gate:** the natives take **script hValue handles** for the context and the page root (RefCounter conversion), not the
raw engine objects; the handle/wrapper relation is not derived, so a host call with the engine objects would be a guess.
Focus, page stack, cursor and back are script state; a host page bypasses `onInitialize`/`reflect`/`apply` and must own
focus/input/back. **Smallest next step:** find the context handle and the hidden page-root handle (`MonitorRoot`), call
`startPage` from a dispatch hook and capture a headless frame; then prove back and focus/input. No page was implemented
or faked; Phase 1c is complete and committed (`c9c461ab`). Design in mapping §18.
