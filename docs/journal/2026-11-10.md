  - **Why.** The owner's complaint is stutter, not the average. The streamer's rc14 log (GTX 1660 class) shows a steady
    race GPU busy of 6.82 ms but 1,258 race spikes with a mean GPU wait of 17.3 ms, a p99 of 75 ms, and a 0.856
    correlation between frame wall and GPU wait. `cpu_summary.py` reported averages only, with p50/p95 in a few places:
    no p99, no 1% low, no counts of frames over 16.7/20 ms, no per-interval trace, no scene tag. The owner's controlled
    slow-CPU (3.4 GHz) and slow-GPU (underclocked RX 9060 XT) baselines were coming.
  - **Old table stays.** `cpu_summary.py` keeps the TASK-027 averages table and its keys; `--table-only` prints only
    it. The compatibility test runs the pre-change tool (from git) and the new one on the same synthetic log and compares
    the output line for line: 61 of 61 identical.
  - **New sections per run:** `stutter` (intervals over 16.7 ms, worst interval and its VBlank, share over budget, 1%
    low), `statistics` (p50/p95/p99 by nearest rank as `native/perf_probe.cpp`, 1% low = 1000/p99, max, counts and ratios
    over 16.7 and 20 ms; `--stats all` covers every old metric), the N worst intervals with wall, GS worker, process CPU,
    GPU busy, GPU wait, submissions, prims and batches, and a text histogram.
  - **CSV:** `--csv` or `GT4_BENCH_CSV` writes one row per `[core2]` report interval (VBlank range, wall, GS worker,
    process CPU, GS exclusive total, EE critical path, GPU busy/draw passes, `gpu_wait` and every printed reason,
    readbacks per reason, submissions, uploads, CLUT loads, swizzle KiB, prims, fragments, batches, draws, readbacks) and
    a `<name>-spikes.csv` sidecar with one row per `[core2] spike` VBlank. A run without `[core2]` blocks (GSdx, CoreGS
    1.1) falls back to its `[hw] cost` intervals.
  - **The per-frame sources were already in the renderer.** `[core2] spike` (`GT4_CORE2_SPIKE_MS`, default 20, off with
    0; `GT4_CORE2_SPIKE_LINES`, default 40 per 600 VBlanks) is a thresholded per-VBlank trace; with `0.01` and a high cap
    it is complete, and the summary computes per-VBlank p99/1% low only when the lines cover >= 98% of the window,
    otherwise it reports the trace as censored. `GT4_HW_FRAMETIME_LOG` gives real presented/shown frame intervals; the
    summary reads the run folder's `frametime.csv` and adds a per-frame table and stutter line.
  - **Scene tag:** `GT4_BENCH_SCENE`, `--scene`, and a `scene.txt` that `common.sh`'s `record_scene` writes in
    `night-run.sh`, `arcade-run.sh`, `spec2-run.sh`, `replay-run.sh`, `replay-gsdx.sh` (defaults `night`, `ssr5-night`,
    `spec2-<scene>`, the recording name); `cpu_summary.py` reads the file so an old run is never guessed from VBlank
    ranges. Every CSV row and every section header carries the tag.
  - **EE attribution:** `[frame] critical path=` has no VBlank; the CSV places each report in the interval where the
    cumulative `N VBlank samples` of `[perf]` ends, which is the only printed bridge. The report is averaged when two
    land in one interval.
