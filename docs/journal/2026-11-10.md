## TASK-213 Phase 1d: a live Resolution and the game's own OptionMenu rows (branch `task/213-native-settings`)

The owner's Phase 1c test: the Screen labels and values worked, but confirming Resolution changed only the row and the
`game-changes.toml`; the actual screen stayed at the desktop mode. And the sliders were the wrong widget for both rows.

### The live resolution finding

- The launcher's Resolution is an **output size** (`GT4_OUTPUT_SIZE`), read once at start and used for the window
  client/aspect and the launcher's internal GS scale. Fullscreen is a borderless window covering the monitor's current
  `rcMonitor`, so the monitor mode never changed. The Phase 1c row was restart-only and the kit bypasses the launcher,
  so nothing applied. The correct fix is a **true display-mode change** in fullscreen (`ChangeDisplaySettingsExW`),
  a **client resize** in windowed, and a live aspect ratio; a render-scale change is not live (CoreGS sets
  `GT4_HW_SCALE` at construction; GSdx is a separate process).
- Implemented in `native/window.cpp`: `apply_display_mode` (enumerate the monitor, prefer the current refresh, save the
  original `DEVMODE`, `ChangeDisplaySettingsExW(CDS_FULLSCREEN)`, window to the new `rcMonitor`),
  `restore_display_mode` (fullscreen Off, WM_DESTROY, cleanup), `apply_output_size` (fullscreen display mode or
  windowed `AdjustWindowRectEx` + `SetWindowPos`), and the start apply from `GT4_OUTPUT_SIZE`.
  `native/display_aspect.*` gained `set_live_output_size` (the ratio used by the next race camera/HUD block; a fixed
  `GT4_DISPLAY_ASPECT` still wins). The window consumes `native_settings::request_output_size` at the VBlank.

### The dropdown rows

- The page script owns the `Vertical`/`Horizontal` `SliderBar` modules, so the row type cannot be changed under them.
  The data-only route (section 12.2 of the map) was used: Pane stays 320x150, the stock sliders get `visible 0`,
  and two scriptless `OptionMenu` rows (`Resolution` 29 choices, `Monitor` 1) are inserted before `HiVision`. The engine
  draws the closed row, popup, focus frame and scrolling and handles the pad; the host reads the index `+0xD8`, count
  `+0xE0` and open flag `+0xFC` at the render functor `0x00100F50`, applies on the closed transition, and writes the
  feedback. The hidden sliders' `screen_adjust_v/h` still return 0 and skip the setters: the guest save stays 0
  (states: `screen_adjust_v/h` 0, wide 1, `opti`).
- The first choice is 1920x1080 (the kit start) so the closed row is right at page open; the 29-item popup scrolls
  (frames). A host text injection on the OptionMenu was attempted and crashed (`no translated code at 0x00617D04`): the
  engine's closed-label clone shares the localized text object; the data literals are used instead.
- The greyed state (Fullscreen Off) uses `mWidget +0x98` bit 3 on the OptionMenus and their children; Down skips them
  and lands on OK.
