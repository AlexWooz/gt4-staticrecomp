## Owner fidelity directive for CoreGS 3.0

The owner confirmed (Telegram, 2026-11-10): CoreGS 3.0 does not need to match CoreGS 2.0/GSdx pixel for pixel; the goal
is to get close and then iterate on lights, reflections and missing effects. The measured image and performance gates
are a compass, not a bit-exact acceptance gate. This matches the AGENTS/TASK-090 wording ("fidelity is a measured,
per-scene target, not a bit-exact gate"); it is recorded here as the owner's confirmation for the implementation work.

## Owner clarification: 100% decoupled presentation (CoreGS 3.0)

The owner clarified (Telegram, 2026-11-10) that CoreGS 3.0's presentation must be fully decoupled from the guest's 60 Hz
tick, like a modern game: an arbitrary, constant presentation rate (20, 30, 45, 60, 120, 144 Hz or VRR) with a stable
frame time, not the uneven cadence of CoreGS 2.0's frame skipping. The renderer samples the timeline at the presentation
instant and interpolates the two latest 60 Hz guest states; it cannot ask the guest physics for an arbitrary instant
because the game only computes at 60 Hz. Prediction/extrapolation remains an optional later switch; the default
interpolation costs about one guest frame of latency. The plan section 5.5 and the timeline structures already cover
this; wiring the presentation scheduler into the live renderer is still pending.

## Prediction study: rigid predictor and pose camera (2026-11-10)

- Three 32-frame windows of the deterministic B-Spec night race (seq1 7398-7429, seq2 8000-8031, seq3 9500-9531; static
  camera, followed car, fast pan/zoom) measured prediction vs the captured tick.
- Entrywise matrix extrapolation is exact for car bodies and the camera (<=0.05 px) but distorts spinning wheels by
  12-22.6 px at 1x (36-68 px at 3x) in every window (wheel spin 0.8-1.3 rad/tick). It is not safe globally.
- A rigid predictor (linear world translation, quaternion constant angular velocity, linear scale) with an entrywise
  fallback for rank-deficient flat shell/reflection draws gives a tick correction of <=0.37 px for bodies and <=0.9 px
  for the worst followed-car wheel at 1x (2.7 px at 3x), p95 <=0.2 px.
- The camera must be predicted from its pose (position + orientation) with a constant angular acceleration term:
  entrywise V extrapolation shifts a fast pan by 0.56-0.75 px, the pose model by 0.04-0.08 px.
- Interpolation needs the same rigid treatment for wheels: entrywise lerp wobbles them by 0.9-6.1 px at 120 Hz; rigid
  slerp is <=0.42 px. A player-car-only hybrid is not justified; the split is part-class and camera-driven.
- Discontinuities (collisions, resets, camera cuts) must drop the prediction for that tick. The study covers straight
  near-constant-speed B-Spec running only; braking/cornering, human input, collisions, cuts and course objects are
  unmeasured. Evidence: `build/analysis-prediction/`.

## First textured offline car frame (TASK-090, branch `task/090-textured-render`)

- **Sampler (`native/coregs3/coregs3_sampler.{hpp,cpp}`, always built).** The measured car-pass subset, in GS terms:

## Body/paint environment-map reflection in the offline renderer (TASK-090, branch `task/090-body-reflection`)

The offline reference renderer draws the car body/paint reflection pass. One problem, one writer, in a dedicated
worktree from `task/090-coregs3` at 00150e49.

- **Draw and item identification.** The reflection pass is the body/paint item's only captured draw (program dispatch
  0x1058, six-qword block, tag PRIM 0x7C), not a second draw in the `.gt4scene`: the tap's reflection record for the
  item carries TEX0 0x2BC0 (the CT32 256x256 environment map, the item's own 40-byte record) and the measured
  additive/DATE/GEQUAL state. The *base* pass that writes the destination alpha is a different captured draw: the
  nine-qword/three-qword items that share the reflection item's vertex positions (the tap proves 27 exact geometry
  pairs, e.g. draw 4 -> 5, draw 6 -> 7, draw 10 -> 11/12); they are rendered by the existing textured path, so the
  framebuffer alpha the reflection tests is the real base MODULATE alpha. Where the base is not captured, the DATE test
  runs against the offline background's alpha and is counted.
- **Formula (`native/coregs3/coregs3_reflection.{hpp,cpp}`).** The pinned float32 texgen: `D = P - LP`, `c = N·D`,
  `R = D - 2*N*c`, `V = C9*R.x + CA*R.y + CB*R.z`, `W = V/|V| + (0,0,1)`, `q = 0.5/|W|`, `S = 0.5 + W.x*q`,
  `T = 0.5 - W.y*q`, with the item's own six-qword block (command 0x6C06C0C9), the raw V3-16 position and the V3-8
  normal /127. Every outside form is a named refusal (block, position, normal, non-finite, degenerate zero W).
- **Pass (`coregs3_render`).** The body/paint item's triangles are rasterised as the measured additive pass: the map is
  sampled with the measured sampler (linear/linear, region clamp 0..255), MODULATE's C is the lit vertex colour, the
  GS fog mixes toward FOGCOL black with the tapped per-vertex fog `(f*c + (255-f)*fc)>>8`, the ATE/ATST/AREF test runs
  first, then the destination alpha test (DATE/DATM against the framebuffer alpha), the GEQUAL depth test (the two
  draws' float projections can differ by ~1e-4 relative where the GS's 24-bit Z is identical, so a 1e-3 relative window
  reproduces the equal-depth pass), the additive blend `(Cs-0)*Ad+Cd`, FBMSK and ZBUF's no depth write. The reflection
  mask marks the written fragments.
- **Correction: PRIM.ABE is bit 6.** The sampler read ABE as bit 0; the GS register and `hw_gs` `primbit::kAbe` say bit
  6. Every measured car PRIM is even (base 0x3C, reflection 0x7C), so the mistake was invisible until the reflection's
  additive equation needed the difference; with the fix the measured default is the base PRIM 0x3C and five items whose
  ALPHA equation is outside the measured normal/additive pairs become explicit counted blend refusals.
- **Table (`coregs3_texture_frame`).** In reflection mode the body/paint items bind their CT32 record as the reflection
  map (no model UV), attach the tapped PRIM 0x7C state plus the record's per-vertex fog, and count the items without a
